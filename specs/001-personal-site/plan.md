# Implementation Plan: davd.fr — Personal Website, Portfolio & Wiki

**Branch**: `001-personal-site` | **Date**: 2026-07-10 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-personal-site/spec.md`

## Summary

Build a fast, static personal website for David served at `davd.fr`. It introduces
who David is (home/about), showcases his projects (portfolio), and hosts a personal
wiki (knowledge base). Projects and wiki entries are Markdown files with typed
frontmatter, so publishing is "add a file, push." The site is generated by Astro,
ships near-zero JavaScript, supports light/dark, and deploys to GitHub Pages via
GitHub Actions on the custom domain.

## Technical Context

**Language/Version**: TypeScript / Node.js 22, Astro 5

**Primary Dependencies**: `astro`, `@astrojs/sitemap`; Astro built-in Content
Collections + Markdown/MDX. Hand-written CSS (no UI framework).

**Storage**: Flat files — Markdown content in `src/content/`, site profile in a single
typed data module. No database.

**Testing**: `astro check` (types) + `astro build` as the build-time gate (schema
validation of all content, broken-link surface). Manual/Lighthouse verification of
rendered output. (No unit-test framework — YAGNI for a static content site.)

**Target Platform**: Static HTML/CSS/JS hosted on GitHub Pages behind the `davd.fr`
custom domain, served over a CDN.

**Project Type**: Static web (single project, content-driven).

**Performance Goals**: Lighthouse Performance & Accessibility ≥ 95; no render-blocking
third-party requests; total CSS well under budget; content pages ship 0 KB of JS
unless a component opts in.

**Constraints**: Must work with JavaScript disabled; responsive from 360px; respects
`prefers-color-scheme` and `prefers-reduced-motion`; build MUST fail on invalid
content frontmatter.

**Scale/Scope**: One person's site. Dozens of projects and wiki entries expected over
time; a handful seeded now. ~5 route types (home, projects list/detail, wiki
list/detail, 404).

```text
    ├── wiki/index.astro
    ├── wiki/[...slug].astro
    └── 404.astro
.github/workflows/deploy.yml  # Build + deploy to GitHub Pages
```

**Structure Decision**: Single static project at repo root (Astro convention). Content
lives in `src/content/{projects,wiki}` as Markdown; schemas in `src/content/config.ts`
are the enforced contract. Site profile is a single typed module (`src/config/site.ts`)
so the home page and footer share one source of truth. This layout directly satisfies
"Content Over Code": every new project or note is a single Markdown file, and the
dynamic `[...slug]` routes render it with no further edits.
